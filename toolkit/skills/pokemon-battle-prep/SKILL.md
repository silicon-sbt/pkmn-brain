# 赛前准备 + 战中纪律

> 路径以**本仓库根**为基准。若本仓库是别的项目的子目录（如 `toolkit/`），
> 把 `tools/` 读作 `toolkit/tools/`、`teams/` 读作 `toolkit/teams/`。

## ⛔ 战斗中的铁律（最重要，违反过）

**每回合的回答 ≤ 1 行。禁止表格、禁止推理、禁止解释。**

正确：`点冰旋。`
错误：

> 从对位表看，冰旋对它 66-78% 稳两确，而它的地震打你只有 14-17%，所以……

**为什么**：实测工具只要 0.16 秒，战斗中慢的**不是计算，是模型写长回答**。
真人对战每回合只有 60-120 秒，写一段分析就等于让用户干等。
**用户问"出谁/点啥"时，答案是几个字，不是一份报告。**

需要解释的复盘留到**打完之后**做。

## 战前流程

### 第 1 步：必须问清对手信息（不能跳）

**不要跳过这一步直接算。** 我方的模型记忆对具体玩家一无所知，
而"猜的配置"会让整张战斗卡失准。

要问：
- 对手的队伍是什么？（有截图/文本最好）
- **他平时爱用什么招/什么怪？**（哪怕只是印象也极有价值）
- 你们之前打过吗？他上次用什么？

> 实战教训：我曾按猜测配置生成战斗卡，结果天蝎王、盐石巨灵、
> 骨纹巨声鳄三只的道具/招式/EV 全部猜错。对手用一手「掉包」
> 把火焰宝珠塞给我的主力，**烧伤使攻击减半，整局报废**——
> 而我的表里根本没有"掉包"这条。

### 第 2 步：生成战斗卡

```powershell
node tools/battlecard.mjs teams/我方.txt teams/对手.txt [威胁数]
```

产出 `battlecard.md`，含三部分：
- **A 表**：我方每只对每个威胁的最佳招 / 伤害 / 几确
- **B 表**：对手招式清单
- **C 表**：**干扰与异常预警**（道具破坏 / 异常状态 / 撒钉 / 清强化 / 先制）

**读完整份卡再开打。战斗中不再调工具。**

### 第 3 步：确定首发与 Plan

- 首发要选**对对手大部分成员都不吃亏**的那只。
- 同时想好：如果首发被压制，换谁上。

## 战斗中

- 用户报场面（对面出什么 / 我场上是哪只 / 血量），**直接回出招**。
- **不调工具**。表已经在上下文里。
- 只有遇到表里没有的宝可梦时，才说"这个要算一下"，并跑一次极速查询（`node tools/q.mjs`，
  或把仓库根下的 `q.cmd` 放进 PATH 后直接敲 `q 雄伟牙 天蝎王`）。
- 用户赶时间可以让他自己敲：`q 雄伟牙 天蝎王`

## ★ 只看伤害是不够的

**"算伤害"不等于"算威胁"。** 一次实战中，伤害全部算对，
但对手一手换道具就把主力废了。所以每次准备都要过一遍：

| 类别 | 要警惕的招 |
|---|---|
| **道具破坏** | 拍落、掉包、戏法、抢夺 |
| **异常状态** | 剧毒、磷火、电磁波、蘑菇孢子、催眠 |
| **持续消耗** | 盐腌、寄生种子、束缚类 |
| **清除强化** | 黑雾、清除之烟、Unaware 特性 |
| **先制** | 偷袭、神速、青草滑梯、水手里剑 |

## 打完之后

复盘放到这里做，而不是战斗中：
1. 哪些判断对了、哪些错了（**Tera 是常见的失效原因**）
2. 对手实际配置和假设差在哪 → 更新对手队伍文件
3. 哪只从头到尾没发挥作用 → 考虑换掉
